How it works

  1. The problem

    Standard vector RAG fails on complex documents where entities and concepts are deeply interconnected. It needed hybrid retrieval: dense vector search plus structured knowledge-graph traversal.

  2. Graph RAG architecture

    Neo4j stores entities and relationships extracted from documents alongside a FAISS vector index, enabling multi-hop reasoning and relationship-aware retrieval that flat vector search cannot do.

  3. Reranking pipeline

    Candidates from FAISS and Neo4j are scored by a cross-encoder reranker and fused before reaching GPT-4, significantly improving precision on complex multi-entity queries.

  4. Multimodal layer

    CLIP image embeddings and GPT-4V visual question answering extend retrieval across PDFs, images and tables.

  5. Deployment

    A Gradio web app with multi-turn conversation, source attribution per answer, and a trace panel showing which graph paths and vector chunks contributed.
